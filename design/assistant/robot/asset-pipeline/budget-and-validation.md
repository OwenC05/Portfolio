## How to settle an allocation

1. Studio owner supplies the exact integrated room candidate, camera, controller, dependency lock and production build/route-graph hashes. Root resolves whether the assistant will integrate against current pilot or later full kit; do not mix pilot camera, M3 images, M4 offline counts and old framework JS as one baseline.
2. In the owner's later build/capture slot, measure baseline Studio cold/warm transfer and all required frames at real desktop/small DPR. Inventory unique URLs once per scenario and actual `Content-Encoding`, `encodedBodySize`, decoded bytes and `transferSize` overhead. Count scene dependencies and lazy chunks fetched when the assistant opens, including retained `/ask` code where shared; do not sum duplicate shared chunks twice or use every route's JS as an exact measurement. Network evidence must pin build and cache conditions.
3. Compare the same revision with robot mesh only; then add eyes/motion code, then 0/1/4 real marks and accessible panel/shared-state code. Record incremental raw/gzip/Brotli JS, asset bytes, unique/placed triangles, geometry/material/texture counts, decoded image memory estimates, measured calls/triangles and scheduling. Separate imported static eyes from runtime-generated eyes to avoid double counting. Four mark instances may share geometry/material but still incur multiple submissions unless a measured implementation batches them.
4. Measure first render, explicit shadow refresh, settled idle, active finite gestures and changing marks at every required view and look extreme. Count full rendered frames including extra passes; moving parts with no casting still add main-pass work. No synthetic ambient loop. Measure no-animation settled state, hidden/offscreen suspension, live reduced motion, late load and disposal separately. `renderer.info.memory` counts resources, not VRAM bytes; a raw RGBA estimate `sum(width*height*4)` plus approximately 1/3 for a complete mip chain is an estimate, not driver/GPU measurement.
5. Proposed allocation equation for each metric: `assistant_available = hard_limit - measured_baseline_peak - approved_remaining_room_work - root_reserved_contingency`. Negative or unknown terms mean **no assignable capacity yet**. Assistant allocation must include GLB, dynamic eyes, all marks, JS/chunks and any pass/scheduling cost. Stage/design ceilings may be tighter than hard limits and remain binding. Root explicitly assigns the split after Studio owner concurrence; B does not spend margins or invent numeric robot caps.
6. If capacity fails, hand root a measured assistant-only reduction option (e.g. redundant hidden geometry/material consolidation inside rigid boundaries, smaller validated image) and a new version for A review. Room-wide T1/optimization, reserve use, decoder dependencies, camera changes or gate loosening remain separate owner decisions. Unimplemented savings count as zero.

## Technical candidate validation checklist

The preparation validator in [verify-package.mjs](verify-package.mjs) checks this package, paths, example invariants and arithmetic only. It is **not a production GLB validator**. The future robot validator/loader lane must implement the following against the frozen profile and independently recompute results:

1. **Identity:** profile/candidate/manifest/source/script/export hashes agree, files exist within the candidate package, provenance has no unresolved production fields; exact A version and room/camera target identified. External manifest hash goes in the handoff receipt. Reject a draft/example as production.
2. **GLB bytes:** valid magic/version/length/chunk layout/alignment, one scene/root/BIN, bounded JSON/accessor/image allocations; no trailing malformed payload, URIs or unknown extensions. Set parser safety caps before untrusted input parse, separately from performance allocation.
3. **Geometry/hierarchy:** unique required names, exact parent list, reachability, no cycles/multiple parents, valid index/range/stride/alignment and accessor types, finite positions/normals/UVs/quaternions, in-range indices and declared attributes; recompute triangles, bounds and primitive instances from bytes. Reject missing pivots, negative/sheared transforms, unexpected skeleton/morph/clip or fixture cards.
4. **Coordinates:** source and export basis probes, metre scale and wrapper once, no extra floor translation, correct handedness and fin/eye side convention. Match neutral pivots and swept bounds with stated tolerance. Check constraint-baked motion continuously enough to cover eased overshoot; endpoint boxes alone cannot bound a rotating fin.
5. **Materials/images:** exact material/slot/flag table, allowed extension checks at every level, opaque occluders include nocast meshes; MIME and encoded lengths checked, images actually decoded, dimensions/pixels verified, no missing required browser slot or UV orientation errors. Distinguish no textures from failed decode. Count shared identities only once for storage and separately per rendered placement.
6. **Motion/state:** selected variant only; if clips, validate duration/keys/paths/rest pose and interruption; if runtime poses, bind the exact node names and bounded values. Truthful current-run 0/1/4 marks, no baked placeholders, no stale run/chip mismatch, no artificial generation phase, live reduced-motion stop and late-load settled state. C owns state policy/tests.
7. **Lifecycle:** abort before/during load, image failure after mesh allocation, supersession, delayed decode, repeated mount/unmount and context loss; release each owned allocation once, drain late work, revoke URLs, close owned bitmaps, cancel scheduling. Robot failure leaves usable HTML/source/contact access.
8. **Integrated measurement:** final encoded delivery, peak/forced-refresh/settled counters and scheduling at target DPR, 320/390/desktop, all look bounds, modal states and gesture extrema. Record source and browser/device identifiers. Independent A/Claude visual verdict and Studio-owner/root gate are separate from structural checks.
