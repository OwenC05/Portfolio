## Required correction: bind the actual row payload

`pinning.sources` correctly hashes the supplied source bytes, and the independently frozen declaration digest protects row identities, group ranges/classes and support intent. However, `rowsArgument` supplies the actual vertices, polygons and corner normals separately. Neither their values nor their derivation is bound to those source hashes. “Same order as source” is a stated requirement with no verifiable association in the interface.

For example, a caller could supply different vertices or corner normals with the same declared counts, ranges, classes and source bytes. If that alternate geometry passes the support/normal predicates, the current interface could report a valid declared-source result without establishing that it checked geometry produced by those sources. This is an evidence-association gap, not a claim that the implementation already has a particular bug.

**Smallest correction, retaining the same API:** add a required `rowsSha256` to the externally frozen declaration, computed over the canonical complete rows payload—including vertices, faces, live groups/classes and supplied corner normals—using a precisely specified finite JSON encoding, such as the declaration's existing Python canonicalization. The verifier recomputes the supplied payload hash and rejects disagreement. Do not derive or update the *expected* row digest from the candidate during verification. State that source-candidate integration must first reproduce that exact payload from the declared, hash-verified geometry-producing sources through the named producer entrypoint; preserve the association in a small technical receipt. This is a source-stage check and needs no runtime/glTF schema change or new broad validator workflow.

A rows digest binds evidence identity; it does **not** prove the payload was generated by a source. The reproducible producer/integration check supplies that association. Likewise, a source or declaration digest cannot prove that an artist named every support correctly. Keep actual Claude's semantic authorship/completeness and root/S's independent freeze as explicit prerequisites. Narrow fixtures must retain `scope: fixture`; they cannot establish complete candidate intent.

## V1–V3 coverage otherwise specified adequately

- **V1:** `declaration.supports` and `supportMeaning.primitive` require stable independent contact identities, all intended supports including kick spurs, and no lowest-vertex-derived inventory. Complete-primitive minimum Z with the fixed 0.3 mm gap and **signed ±1 µm** tolerance catches both lift and penetration. Every support selects an explicit receiving surface, and all supports in a floor-supported row must agree on the surface.
- **V2:** surfaces reference actual declared boundary faces. The complete projected convex footprint, actual inner field/outer outline, 20 mm inside/outside clearance, edge crossing and enclosure checks address rounded corners and full-footprint omissions. Horizontal simple convex boundary support is explicit; unsupported shapes fail closed. The stated convex-hull conservatism is acceptable as a declared technical limitation, not a new art rule.
- **V3:** exact externally pinned row/group identities, ranges/counts and full face-class arrays prevent missing, duplicate, unknown or unpinned reclassification from shrinking the tested scope. Every vertex/face must have exactly one group. All N1 rows require supplied finite unit corner normals, nondegenerate fan triangles and planar polygons; planar corners use oriented `dot >= cos(2°)`, regardless of area. Bevel/round faces remain valid-normal scope but are excluded from the flat-panel assertion. Classes must originate from Claude's declaration, never the normals being checked.

The expected declaration digest must remain an independent root/S input, not `hash(declaration)` computed and passed by the same candidate call. Complete source/row/support/surface identity checks and the exact class arrays are meaningful only against that frozen expected scope. Reject rather than infer missing declarations; current v03's absent complete approved declaration therefore cannot pass.

All calculations remain **source-only Blender metres, Z-up**, with positions, boundary heights and supplied normals in the same frame. Final exported triangle/group correspondence and actual glTF POSITION/NORMAL/index validation remain the explicitly separate later gate. G1 geometry repair, V4 edge semantics, embedding intent, rug/decal wording, images and stage acceptance stay with their existing owners. `candidateAcceptance: false` remains appropriate even when the bounded source checks pass.

After the narrow payload-binding amendment, the interface is suitable for implementation review. No additional artistic scope, geometry redesign or verification framework is requested. This bounded interface review is complete.
